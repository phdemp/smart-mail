<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → POST /reclassify | User-submitted category value crosses trust boundary; must be validated against CATEGORIES enum |
| Browser → POST /feedback | User-submitted vote and classification_id cross trust boundary; both require validation and ownership check |
| Server → SSE broadcast | classification_updated event data reaches all connected clients for this user; no cross-user data in payload |
| api.js → sender_rules | Rule promotion query must scope to (user_id, domain, category) tuple |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | /reclassify category input | mitigate | category validated against validCategories array before any DB write; invalid value returns 400 (V5 ASVS L1) |
| T-03-11 | Tampering | /reclassify email ownership | mitigate | SELECT id, from_address FROM emails WHERE id = ? AND user_id = ? — ownership verified before DELETE/INSERT (V4 ASVS L1) |
| T-03-12 | Tampering | /feedback vote input | mitigate | vote validated in ['up','down'] before DB write; SQLite CHECK constraint is defense-in-depth (V5 ASVS L1) |
| T-03-13 | Tampering | /feedback classification ownership | mitigate | cls looked up via WHERE email_id = ? AND user_id = ? — cross-user feedback pollution structurally prevented (V4 ASVS L1) |
| T-03-14 | Tampering | sender_rules COUNT query cross-user | mitigate | COUNT query includes c.user_id = ? as first predicate; cross-user rule promotion is impossible (V4 ASVS L1) |
| T-03-15 | Tampering | SSE broadcast data | accept | broadcast() sends to all connected SSE clients (all users); classification_updated payload contains email_id and category which are low-sensitivity; no PII in payload |
| T-03-16 | Elevation of Privilege | setBroadcast injection circular require | accept | setBroadcast is injected after mount — not via circular require; server.js owns broadcast; risk of injection by malicious module is out of scope for local Node.js app |
| T-03-17 | Information Disclosure | correction history in detail fragment | mitigate | detail fragment is served to the authenticated owner of the email only (existing email ownership check in GET /api/emails/:id); corrected_at and user_corrected_category visible only to the correcting user |
</threat_model>
