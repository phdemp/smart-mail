  <behavior>
    stripQuotedReplies:
    - Input 'Hello\n> quoted\nWorld' → output 'Hello\nWorld'
    - Input containing a line 'On Mon, Jan 1 2024 Alice wrote:' → that line removed
    - Input containing '--- Original Message ---' → that line removed
    - Input of 50 chars that is all > lines (stripped result = 0 chars) → returns original 50-char string
    - Input of 200 chars that is 90% > lines (stripped = 15 chars) → returns original because stripped.length(15) < 100 AND original.length(200) > stripped.length(15)
    - Input already clean (no > lines) → returned unchanged

    buildThreadContext:
    - null input → null
    - [] input → null
    - Array of 7 messages → result contains at most 5 [From: blocks
    - Array of 5 messages each with 600-char body → result.length <= 6000
    - Each message formatted as: '[From: {name} <{addr}>]\n[Subject: {subj}]\n{body_snippet}'
    - Messages ordered oldest-first (input ordering preserved; caller is responsible for ordering)
    - When total exceeds 6000 chars, oldest message (first in array after slice(-5)) is dropped first

    fetchThreadContext(userId, email):
    - Returns [] when email.raw_headers is null and subject is empty
    - Returns only emails WHERE user_id = userId (never emails of other users)
    - Does NOT include the triggering email itself in results (WHERE id != email.id)
    - When email.raw_headers contains valid JSON with 'in-reply-to' value matching a stored email's message_id, returns that email via the header path
    - When raw_headers is null/empty, uses subject-normalized fallback with REPLACE chain
    - Subject normalization is case-insensitive: 'RE: Hello' and 're: Hello' and 'hello' all normalize to 'hello'
    - Results limited to 5 rows (LIMIT 5)
    - Results filtered to within 90 days (subject fallback only)
  </behavior>

| fetchThreadContext → SQLite | Parameterized queries prevent SQL injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-07 | Information Disclosure | fetchThreadContext cross-user leakage | mitigate | CRITICAL: every SELECT in fetchThreadContext includes AND user_id = ? as a bind parameter — not string interpolation. | T-02-08 | Tampering | Prompt injection via thread body text | mitigate | stripQuotedReplies reduces content; buildThreadContext truncates each message to 500 chars; labeled section headers (## Prior thread context / ## Current email) added in Plan 04 provide structural separation in the LLM prompt |
| T-02-09 | Denial of Service | fetchThreadContext regex on large body_text | accept | body_text is already stored truncated at 100,000 chars in storeEmail(); the regex operations are line-by-line splits, not catastrophic backtracking patterns |
| T-02-10 | Spoofing | Malicious raw_headers JSON | accept | JSON.parse result is only used for string equality matching against message_id values; never eval'd, never executed, never used to construct SQL outside of parameterized placeholders |
