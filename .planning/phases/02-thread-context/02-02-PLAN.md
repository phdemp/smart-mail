<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IMAP server → storeEmail() | parsed object from mailparser contains untrusted email header values |
| application → llm_logs | log entries written by server; no external input path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Information Disclosure | llm_logs.user_id | mitigate | llm_logs rows are written server-side only; no API endpoint exposes this table in Phase 2 (Phase 4 adds the health endpoint with auth guard) |
| T-02-04 | Denial of Service | llm_logs unbounded growth | mitigate | 30-day pruning DELETE on every server startup (D-11); single synchronous operation, no background job |
| T-02-05 | Tampering | raw_headers JSON injection via IMAP | accept | raw_headers is stored as-is and later JSON.parse'd in thread.js; the parse result is only used for message-id matching (string equality), not eval'd or executed; no code execution risk |
| T-02-06 | Information Disclosure | idx_emails_msgid_user index covers user_id | mitigate | Index is on (user_id, message_id) — every query using this index must also filter by user_id, which is enforced in fetchThreadContext per V4 cross-user isolation requirement |
</threat_model>
