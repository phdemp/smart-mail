## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /api/llm/health | Authenticated: req.user.id is set by requireAuth middleware before route handler executes |
| client → GET /api/llm/health/pill | Authenticated: same global middleware applies |
| provider error messages → HTML | last_error_msg is LLM-provider-generated; must never reach the pill HTML (only "AI features degraded" appears there) |
| LLM provider → router | Malformed 200 response (soft fail): content is invalid JSON or has null category — cascade fallback fires, no result accepted |

Verify new routes are absent from PUBLIC_API_PATHS. Response scoped to req.user.id via getProviderHealth(req.user.id) (V4 ASVS L1) |

| T-04-03 | Tampering | LLM provider response → router.js | mitigate | Soft-failure gate validates category against CATEGORIES enum and summary non-empty BEFORE accepting the result. Invalid results trigger cascade, not silent acceptance (OBSERVE-06) |
| T-04-04 | Elevation of Privilege | User A queries User B's health | mitigate | getProviderHealth(req.user.id) — breaker keys are prefixed userId::providerName in router.js; cross-user leakage is impossible (V4 ASVS L1) |
