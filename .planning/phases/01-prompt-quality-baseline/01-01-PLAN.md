| script stdout → developer | accuracy report is developer-visible; may contain email snippet in error output — acceptable at INFO level |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Elevation of Privilege | scripts/eval-corpus.js --export | mitigate | Open intellimail.db with `{ readonly: true }` option in better-sqlite3. Script never calls INSERT/UPDATE/DELETE. |
| T-01-02 | Elevation of Privilege | scripts/eval-corpus.js --score (DB write risk) | mitigate | Set process.env.DB_PATH to os.tmpdir() throwaway path as FIRST statement before any src/ require. Prevents storeClassification() from writing to production DB even if accidentally invoked. |
| T-01-03 | Information Disclosure | corpus.json (email content) | accept | corpus.json contains real email subjects and body_snippets. File lives in .planning/eval/ which is developer-only. Not committed to the public repo. Acceptable risk for a developer tool. |
| T-01-04 | Tampering | corpus.json ground_truth_category values | accept | Manual labels are set by the developer. No validation at write time — CATEGORIES enum check occurs in --score mode at read time, and entries with invalid categories are skipped with a warning printed to stdout. |
</threat_model>
