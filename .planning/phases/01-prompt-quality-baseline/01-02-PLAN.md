```javascript
function buildPrompt(email, opts = {}) {
  const lines = [];
  lines.push(SYSTEM_PROMPT);
  lines.push('');
  lines.push(`From: ${email.from_name || ''} <${email.from_address || ''}>`);
  lines.push(`Subject: ${email.subject || ''}`);
  const body = (email.body_text || email.preview || '').slice(0, 800);
  if (body) lines.push('', body);
  if (opts.mode === 'regen' && opts.tone) {
    lines.push('', `Generate the draft_reply in a ${opts.tone} tone.`);
  }
  return lines.join('\n');
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM response → parseProviderResponse() | Untrusted: the raw string from any LLM provider enters here |
| email content → SYSTEM_PROMPT + buildPrompt() | Untrusted: email subject, from, and body_text are treated as data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | parseProviderResponse() — LLM output poisoning | mitigate | Whitelist check `CATEGORIES.includes(obj.category)` already present at line ~74; out-of-enum values fall back to DEFAULTS.category ('other'). The low_confidence flag is set on fallback so operators can see when the LLM tried to inject a non-enum category. |
| T-02-02 | Information Disclosure | console.warn in parseProviderResponse() — PII in raw response excerpt | mitigate | Log only first 200 chars of raw response (raw.slice(0, 200)). Acceptable for WARN-level developer logs. The excerpt is 200 chars max — unlikely to contain complete PII but may contain email snippets. Logged at WARN not INFO to reduce exposure surface. |
| T-02-03 | Tampering | buildPrompt() / buildDraftPrompt() — prompt injection via email fields | mitigate | Email fields (subject, from_name, from_address, body_text) are placed after labeled section markers (`From:`, `Subject:`, blank line + body). Structural separation prevents injected instructions in the body from being mistaken for classifier instructions. No concatenation of field values into the system section. |
| T-02-04 | Denial of Service | parseProviderResponse() — extremely long raw response | accept | raw.slice(0, 200) for logging only; extractJsonBlock() handles the full raw string. extractJsonBlock() is existing production code — no change. Risk is LLM-provider-side, not in our code. |
</threat_model>
