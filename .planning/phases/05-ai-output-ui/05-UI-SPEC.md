# Phase 5 — UI Design Contract: AI Output UI

> Visual and interaction contract for Phase 5 frontend changes. Generated by gsd-ui-researcher.
> Covers requirements UI-01 through UI-07.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable — Express + HTMX + Alpine.js) |
| Preset | not applicable |
| Component library | none (server-rendered HTMX HTML in src/routes/api.js) |
| Icon library | Unicode emoji (existing pattern — no icon lib) |
| Font stack | Syne (UI labels), IBM Plex Mono (badges/metadata), Literata (email body) |

Design direction: Neomorphism white — single `#f0f0f0` base, double box-shadow depth, no borders on surfaces. Locked from sketch-findings-NeuralInbox/SKILL.md.

IMPORTANT: The existing `public/css/app.css` uses a blue/slate color theme (`--bg-base: #f0f2f7`, `--bg-panel: #ffffff`). Phase 5 introduces neomorphic shadow variables as NEW CSS custom properties that layer on top of the existing system. Do NOT replace existing variables — add `--shadow-convex-sm`, `--shadow-convex`, etc. as new additions to `:root`. The neomorphic shadow scale applies specifically to tier badges, the draft attribution panel, and the tone chip buttons introduced in this phase.

### 1. Tier Attribution Badge — NEW (UI-01)

**Where:** Email list row (inline after category badge), email detail header (same inline position).

**HTML pattern (list row addition):**
```html
<span class="badge badge-tier-{rule|ai|failed}">
  <span class="tier-dot"></span>
  {Rule | AI | AI ? | Failed}
</span>
```

For `low_confidence = 1` with source `llm` or `fallback`:
```html
<span class="badge badge-tier-ai badge-tier-ai--uncertain">
  <span class="tier-dot"></span>
  AI <span class="tier-lc-suffix">?</span>
</span>
```

**CSS classes to add:**

```css
/* Tier dot — shared */
.tier-dot {
  width: 7px;
  height: 7px;
  border-radius: 50%;
  display: inline-block;
  margin-right: 4px;
  flex-shrink: 0;
  box-shadow: var(--shadow-convex-sm);
}

/* Rule tier — green */
.badge-tier-rule {
  background: rgba(16, 185, 129, 0.12);
  color: var(--accent-green);
  box-shadow: var(--shadow-convex-sm);
}
.badge-tier-rule .tier-dot { background: var(--accent-green); }

/* AI tier — blue */
.badge-tier-ai {
  background: rgba(59, 130, 246, 0.12);
  color: var(--accent-blue);
  box-shadow: var(--shadow-convex-sm);
}
.badge-tier-ai .tier-dot { background: var(--accent-blue); }

/* AI uncertain — amber tint overlay */
.badge-tier-ai--uncertain {
  background: rgba(245, 158, 11, 0.08);
}
.tier-lc-suffix {
  color: var(--accent-amber);
  margin-left: 2px;
}

/* Failed tier — red, MUST be convex (constraint from sketch-findings) */
.badge-tier-failed {
  background: rgba(239, 68, 68, 0.12);
  color: var(--accent-red);
  box-shadow: var(--shadow-convex-sm);
}
.badge-tier-failed .tier-dot { background: var(--accent-red); }
```

**Source logic (rendering function — add to api.js):**
```js
function tierBadge(source, lowConfidence) {
  const src = (source || '').toLowerCase();
  let cls, label;
  if (src === 'rule' || src === 'rules') {
    cls = 'badge-tier-rule'; label = 'Rule';
  } else if (src === 'failed') {
    cls = 'badge-tier-failed'; label = 'Failed';
  } else {
    // llm, fallback, or any other value
    cls = 'badge-tier-ai';
    label = lowConfidence
      ? `AI <span class="tier-lc-suffix">?</span>`
      : 'AI';
    if (lowConfidence) cls += ' badge-tier-ai--uncertain';
  }
  return `<span class="badge ${cls}"><span class="tier-dot"></span>${label}</span>`;
}
```

**Placement (list row):** Insert `${tierBadge(email.source, email.low_confidence)}` immediately after `<span class="badge badge-${escHtml(cat)}">` in the badge `div` at ~line 410 of api.js.

**Placement (detail header):** Insert same after the category badge span at ~line 512 of api.js.

### 3. Extracted Key-Fact Line — NEW (UI-03)

**Where:** Email list row only — 3rd text line below the preview text, before the badge row.

**Applies to:** `travel`, `financial`, `meeting_request` categories only. All other categories: no 3rd line rendered.

**Data source:** `email.extracted_data` (JSON string already fetched in the list query). Parse with `parsedExtractedData()` (already available in api.js scope).

**Field selection logic:**
```
travel:          prefer departure_date → format "Flight · {flight_number} · {departure_date}"
                 fallback if no date: "PNR · {pnr}"
financial:       "Due · {amount_due} · {due_date}"
                 if only amount_due: "Due · {amount_due}"
meeting_request: "Meeting · {meeting_date} · {meeting_time}"
                 if only date: "Meeting · {meeting_date}"
```

Discretion applied: departure_date preferred over PNR (from CONTEXT.md discretion note).

**HTML pattern:**
```html
<div class="email-key-fact">{formatted fact string}</div>
```

**CSS to add:**

**Placement in list row template:** Insert between the preview text `<div>` and the badge row `<div>` at ~line 408–409 of api.js.

### 4. Draft Reveal Section — MODIFIED (UI-04, UI-05, UI-07)

**Where:** Email detail panel — the "AI Draft Response" section currently always visible.

**Change:** The entire draft section is hidden by default and revealed only when the Reply button is clicked.

**New Reply button:** Add a visible Reply button to the email detail action zone (below the email body, above the correction affordance). This is the trigger for draft reveal.

**Hidden-by-default HTML structure:**
```html
<!-- Reply trigger button — always visible -->
<button class="action-btn btn-primary draft-reply-trigger"
        @click="draftVisible = true; $nextTick(() => $el.closest('#email-detail').querySelector('.draft-section').scrollIntoView({behavior:'smooth', block:'nearest'}))">
  ↩ Reply
</button>

<!-- Draft section — hidden by default, revealed on Reply click -->
<div class="draft-section"
     x-data="draftEditor({ emailId: '...', ... })"
     x-show="draftVisible"
     x-transition:enter="draft-enter"
     x-transition:enter-start="draft-enter-start"
     x-transition:enter-end="draft-enter-end"
     style="display:none;">

  <!-- Attribution label — shown while draft is being generated and after -->
  <div class="draft-attribution-label">AI draft — review before sending</div>

  <!-- Tone picker — appears immediately on reveal, before draft content -->
  <div class="tone-picker">
    <span class="tone-picker-label">Tone:</span>
    <template x-for="t in ['Brief', 'Formal', 'Warm']">
      <button class="tone-chip"
              :class="{ 'tone-chip--selected': tone === t.toLowerCase() }"
              @click="changeTone(t.toLowerCase())">
        <span x-text="t"></span>
      </button>
    </template>
  </div>

  <!-- Write yourself link — secondary affordance -->
  <button class="draft-skip-link" @click="skipAI()">Write yourself →</button>

  <!-- Draft textarea — hidden until tone selected + regen completes -->
  <div x-show="draftBody || generating">
    <!-- existing textarea markup -->
  </div>
</div>
```

**Alpine state additions to `draftEditor()` in `public/js/app.js`:**
- Add `draftVisible: false` to the outer email detail scope (or pass as prop)
- Update tone options array from `['formal','professional','friendly','brief']` to `['brief', 'formal', 'warm']`
- `changeTone(t)`: sets `tone = t`, immediately fires `POST /api/emails/:id/draft/regen` — no separate Generate button
- `skipAI()`: clears `draftBody`, sets `draftBody = ''`, shows empty textarea for manual input

**Draft reveal behavior:**
1. Reply button clicked → `draftVisible = true` → section slides in (CSS max-height transition)
2. Tone picker appears immediately with three chips (Brief / Formal / Warm)
3. User taps a tone chip → `changeTone()` fires → POST /draft/regen immediately
4. While regen is in flight: textarea visible but disabled at opacity 0.45 (existing "Generating..." state — constraint from sketch-findings)
5. Regen complete → textarea enabled, content populated
6. "Write yourself →" link available at all times after reveal — clears body, enables empty textarea

**Pre-population rule (D-13):** Draft section never pre-populates on email open. Even if a saved draft exists in DB, it loads only after Reply is clicked. The `initialBody` prop is passed as before but the section is `display:none` until Reply.

## Interaction Contracts

### Tier Badge
- Static display element — no click behavior on tier badge itself
- Appears inline in badge row, no animation on page load
- Badge-tier CSS renders synchronously with the server-rendered list row fragment

### Urgency Tooltip (UI-02)
- Trigger: native browser hover (`title` attribute)
- No JavaScript involved
- Display timing: browser default (typically 500ms delay, 3s display)
- Mobile note: `title` attributes do not show on touch devices — accepted trade-off (D-05 decision)

### Extracted Key Fact (UI-03)
- Static display — no interaction
- Truncated with `text-overflow: ellipsis` on overflow

### Reply → Draft Reveal (D-09, D-10)
| Step | Trigger | Result |
|------|---------|--------|
| 1 | Click "↩ Reply" button | `draftVisible = true`; draft section slides in via CSS max-height transition |
| 2 | Draft section visible | Tone picker appears; "Write yourself →" link appears; draft textarea hidden |
| 3 | Click tone chip (Brief / Formal / Warm) | Chip transitions to pressed/selected state; `POST /api/emails/:id/draft/regen` fires immediately with `{tone: 'brief'|'formal'|'warm'}` |
| 4 | Regen in flight | Textarea appears but `disabled`, opacity 0.45 (sketch-findings constraint — no spinner, no skeleton) |
| 5 | Regen complete | Textarea enabled, draft body populated |
| 6 | Click "Write yourself →" | `draftBody = ''`; textarea enabled empty; tone chips deselected |

### Tone Chip Shadow States
| State | Shadow | Color |
|-------|--------|-------|
| Default | `var(--shadow-convex-sm)` | `var(--text-secondary)` |

## Accessibility Requirements

| Requirement | Implementation |
|-------------|----------------|
| Tier badge color alone insufficient | Badge includes text label ("Rule", "AI", "Failed") alongside color dot — never color-only |
| Urgency tooltip on keyboard focus | Add `tabindex="0"` to urgency badge span so keyboard users can trigger browser tooltip via focus |

| Attribution footer | Plain text — no additional aria needed |

| Color contrast | Tier badge text against badge background: accent colors (green #10b981, blue #3b82f6, red #ef4444) against 12% opacity tint of same — minimum 4.5:1 contrast against `--bg-base` background. Verify with browser devtools before sign-off. |

## Anti-Patterns

Derived from sketch-findings-NeuralInbox constraints. These patterns are explicitly prohibited:

| Anti-Pattern | Reason |
|---|---|
| White (#ffffff) fill on tier badge surface or draft section | Destroys neomorphic depth illusion — #ffffff is reserved for shadow light direction only |
| `border: 1px solid` on tier badge, tone chip, or draft section | No borders on neomorphic elements — shadow defines edges |
| Flat FAILED badge (no box-shadow) | Sketch Variant B confirmed flat FAILED badge fails to communicate urgency — convex-sm shadow is required |
| Spinner or skeleton during draft generation | Generating state is: disabled textarea at 0.45 opacity + pulse-dot label. No spinner. No skeleton shimmer. |
| Concave shadow on tier badges or tone chips | Concave shadow = inputs and display areas (inset). Badges and buttons must be convex (raised). |
| Pre-populating draft on email open | Violates D-13 — draft never renders without explicit Reply click |
| Separate "Generate" button after tone selection | Violates D-10 — tone chip tap IS the generate trigger |
| Four tone options | Violates D-11 — exactly three: Brief / Formal / Warm |
| Confidence percentage shown to users | Explicitly out of scope (REQUIREMENTS.md) — low_confidence is surfaced as "?" only |
| `border-radius` < 8px on badges | Neomorphism requires soft corners; use `border-radius: 9999px` (pill) for tier badges, matching existing `.badge` class |
| Attribution footer for Rule or Failed source | Violates D-16 — footer only for source = 'llm' or 'fallback' |
| Model name in attribution footer | model_id not stored in llm_logs — deferred. Do not fabricate a model name. |
| Extracted key fact for fyi / legal / other / pitch / rewards_awards | Violates D-08 — only travel, financial, meeting_request categories |
| JS tooltip for urgency | Violates D-05 — native CSS `title` attribute only, zero JS |
